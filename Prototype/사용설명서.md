# COAST 범용 수동 기록장 프로토타입

이 배포물은 수동으로 입력한 일반 기록과 파일을 관리하는 시험용 프로그램입니다.
실시간 영상 처리, 위치 추적, 레이더 연계, 감시 카메라 제어, 클릭 매크로는 포함하지 않습니다.
초기 구상 전체가 구현된 버전은 아닙니다.

## 준비 및 빌드

외부 라이브러리, 인터넷, PowerShell, 별도 설치 프로그램 없이 실행하도록 작성했습니다.
Windows 10의 .NET Framework C# 컴파일러와 Windows Forms를 사용합니다.
C# 5 문법을 사용하며 Microsoft .NET Framework csc.exe의 지원 여부는 실제 PC에서 확인해야 합니다.

1. 쓰기 가능한 폴더(예: C:\COAST)에 다음 다섯 파일을 저장합니다.
   Program.cs / Core.cs / Dialogs.cs / MainForm.cs / Build.vbs
2. CS 파일은 메모장에서 UTF-8로 저장합니다. VBS는 ASCII 문자만 사용하므로 ANSI로 저장해도 됩니다.
3. 파일 확장명 표시를 켭니다. 파일명이 Core.cs.txt 또는 Build.vbs.txt이면 안 됩니다.
4. 실행 중인 기록장을 닫고 Build.vbs를 더블클릭합니다.
5. 성공하면 CoastNotebook.exe가 생성됩니다. VBS는 EXE를 자동 실행하지 않습니다.
6. 실패하면 같은 폴더의 Build.log를 메모장으로 직접 엽니다. 오류 줄 번호는 해당 CS 파일의 줄 번호입니다.
7. Tests 폴더의 파일은 직접 입력하거나 배포 PC에서 컴파일할 필요가 없습니다.

VBS는 임시 출력 폴더 _build에서 컴파일한 뒤 최종 EXE를 갱신합니다.
2026-11-03 수정본은 cmd.exe를 거치지 않고 WScript.Shell.Exec로 csc.exe를 직접 실행합니다.
컴파일러 실행이 거부되면 Compiler start error와 오류 번호를 표시합니다. 이를 컴파일 오류와 구분합니다.
컴파일 실패 시 기존 EXE를 새 빌드로 교체하지 않습니다.
실행 중인 EXE는 교체가 거부될 수 있으므로 종료 후 재빌드하세요.
VBScript가 PC 정책으로 비활성화되어 있으면 그 정책을 우회하지 마세요.

## 최초 설정

- 설정이 없거나 양식이 올바르지 않으면 설정 창을 표시합니다. 취소하면 종료합니다.
- 기록장 이름, CSV 출력 폴더, 사진 이동 폴더, 항목 목록을 입력합니다.
- 두 폴더는 C:\COAST\CSV처럼 절대 경로로 입력합니다.
- 출력 폴더는 실제 기록 저장/사진 이동 때 만듭니다. 설정 저장 성공이 폴더 접근 성공을 의미하지는 않습니다.
- 항목은 한 줄에 이름|단위로 입력합니다. 예: 문서|건
- 동일한 이름과 단위는 같은 ID를 유지합니다. 이름이나 단위를 바꾸면 새 유형이 됩니다.
- 과거 기록의 항목명과 단위는 변경하지 않습니다. 삭제한 유형도 과거 기록에는 남습니다.
- 일반 일정은 HH:mm|일정 이름 형식으로 입력하며, 빈칸이면 알림이 없습니다.
- 실제 데이터 대신 가상 항목과 사진 복사본으로 먼저 시험하세요.

## 기록 입력과 수정

1. 새 기록을 누르고 일시, 제목, 항목과 수량을 입력합니다.
2. 추가를 누르면 장바구니에 담깁니다. 같은 유형은 합산하며 999를 넘으면 거부합니다.
3. 수량 0도 허용합니다. 최소 하나의 항목은 있어야 합니다.
4. 장바구니 항목은 선택 후 항목 삭제로 제거하고 다시 추가합니다.
5. 저장/수정을 누르면 원본을 먼저 저장하고 CSV를 갱신합니다.
6. 저장 후에는 같은 기록을 계속 편집합니다. 다음 기록은 새 기록을 눌러 시작합니다.
7. 새 기록을 누를 때 현재 시각으로 갱신합니다. 과거 일시 허용, 미래 일시는 거부합니다.
8. 목록에서 기록을 선택하면 수정할 수 있습니다. 수정 이력은 보관하지 않습니다.
9. 저장하지 않은 입력이 있으면 다른 기록 선택, 새 기록, 종료 때 확인합니다.
10. 기록을 영구 삭제하면 프로그램에서 복원할 수 없습니다. 사진 파일은 지우지 않습니다.

목록은 진행/완료 체크박스, 날짜, 검색어를 함께 적용합니다.
둘 다 체크 해제하면 아무 기록도 표시하지 않습니다. 검색은 제목, 내역, 비고를 대상으로 합니다.
과거 기록은 해당 날짜를 선택하거나 모든 날짜를 체크하여 찾습니다.
창은 기본 너비 420px이며, 화면을 벗어나는 내용에는 스크롤을 사용합니다.

## 원본과 CSV

- Data\Records.xml: 설정, 기록, 사진 연결 경로, 도움말, 미완료 CSV 갱신 목록.
- Data\app.lock: 중복 실행을 막기 위해 실행 중 열어 두는 파일. 파일이 존재하는 것 자체는 오류가 아닙니다.
- CSV 출력 폴더\년도\yyyy-MM-dd\Records.csv: 날짜별 열람/출력용 데이터.
- Data\ViewCopies: 열람용 CSV 버튼으로 만든 사본. 이 사본은 자동 삭제하지 않습니다.
- _build: 빌드 중간 출력. Data와 별개입니다.

원본은 실행 파일 옆 Data에 보관합니다. 같은 원본을 동시에 여러 프로그램이 쓰는 구조가 아닙니다.
PC별로 프로그램과 Data 폴더를 따로 보관하세요. 서로의 Data 폴더를 덮어쓰지 마세요.
CSV 출력 경로를 공유폴더로 설정할 경우 PC별로 서로 다른 폴더를 지정해야 합니다.
공유폴더가 없거나 연결이 끊겨도 원본을 먼저 보존하고 CSV 갱신 대기를 표시합니다.
CSV 재시도는 대기 중인 날짜를 다시 출력하며, 성공해야 대기 목록에서 제거합니다.
날짜가 바뀐 기록은 이전 날짜와 새 날짜의 CSV를 모두 갱신합니다.
마지막 기록을 삭제한 날짜의 CSV는 열 제목만 남습니다.

CSV에는 UTF-8 BOM, CRLF 줄바꿈과 큰따옴표 이스케이프를 적용합니다.
문자열이 수식으로 해석될 수 있으면 내보낼 때 앞에 작은따옴표를 추가합니다. 내부 원본은 바꾸지 않습니다.
유형별 수량은 별도 열이며 열 제목에 유형 ID가 들어갑니다. 내역 열에는 당시 이름과 단위가 포함됩니다.
CSV를 외부에서 수정해도 원본에 반영하지 않으며 재출력하면 덮어씁니다.
열람용 사본은 버튼을 누른 시점의 내용입니다. 이후 원본 수정이 이미 열린 사본에 반영되지 않습니다.
한셀/엑셀이 없거나 파일 연결이 없으면 사본 경로와 열기 실패를 안내합니다.
한셀/엑셀 버전에 따른 한글 표시와 열 인식은 실제 PC에서 확인해야 합니다.
설정에서 출력 경로를 바꾸어도 예전 출력 경로의 파일과 이미 복사한 파일은 자동 삭제하지 않습니다.

원본 파일은 임시 파일 작성을 끝낸 뒤 교체하며, 교체가 지원되지 않는 파일시스템이면 오류를 표시합니다.
지원하지 않는 경우 원본을 먼저 삭제하는 방식으로 강행하지 않습니다.
이 방식은 전원 장애나 디스크 고장으로부터 모든 데이터를 보장하는 백업이 아닙니다.

## 사진

1. 기록을 먼저 저장하고 선택합니다. 저장하지 않은 수정이 있으면 사진 작업을 막습니다.
2. 사진 이동에서 JPG/JPEG/PNG/BMP를 여러 개 선택할 수 있습니다. 확장자만 바꾸는 이미지 변환은 하지 않습니다.
3. 지정 사진 폴더\기록날짜 아래로 이름을 바꾸어 옮깁니다.
4. 이름은 기록일시, 제목, 내역, ID 일부와 일련번호로 만듭니다. 긴 이름은 줄입니다.
5. 기존 파일을 덮어쓰지 않습니다. 복사본을 SHA-256으로 검증하고 연결 경로를 원본에 저장한 뒤 선택한 원래 파일을 삭제합니다.
6. 원래 파일을 삭제하지 못하면 '연결·복사만 완료'로 표시하며 두 파일이 남습니다.
7. 실제 이동 완료 수, 복사만 완료한 수, 실패 수를 구분합니다.
8. 기록을 수정하면 연결 사진명도 갱신할지 묻습니다. 사진명 갱신 버튼으로 다시 시도할 수도 있습니다.
9. 파일명 변경은 현재 사진 폴더 안에서 수행합니다. 기록 날짜가 바뀌어도 기존 사진을 새 날짜 폴더로 자동 이동하지 않습니다.
10. 사용자가 이미 지운 사진은 '파일 없음'으로 표시하며 복원하지 않습니다. 보존 기간에 따른 삭제는 프로그램에서 하지 않습니다.
11. 사진 이름 변경 중 일부만 성공할 수 있습니다. 변경 결과와 오류를 확인하세요.
12. 파일 작업과 XML 저장은 서로 다른 작업이므로 작업 도중 강제 종료되면 사진 경로 확인이 필요할 수 있습니다.

프로그램이 선택한 원본 사진을 실제로 이동하므로, 첫 시험에서는 반드시 사진 복사본을 선택하세요.

## 날짜와 일반 일정

시작 시 또는 날짜가 바뀌면 확인 창을 표시하며, 확인 내용을 원본에 저장하기 전까지 신규 입력을 막습니다.
입력 중인 내용과 입력 일시는 유지합니다. 날짜 확인이 입력 시각을 자동으로 오늘로 바꾸지는 않습니다.
기록을 날짜마다 복제하지 않습니다. 진행 기록은 모든 날짜 조회로 찾을 수 있습니다.
날짜 확인 저장에 실패하면 편집 영역을 잠그고 날짜 확인 버튼으로 재시도하게 합니다.
주기 확인 간격은 15초이며 OS 정지/절전/PC 시계 오류가 있으면 정확히 자정에 표시된다고 보장하지 않습니다.

일반 일정은 PC의 현지 시계 기준입니다. 15초마다 확인합니다.
금일 시간이 지났으나 확인하지 않은 알림은 실행/절전 복귀 후 함께 표시합니다.
확인 여부는 저장하므로 재실행해도 같은 일정은 다시 알리지 않습니다.
프로그램이 꺼져 있으면 알림은 작동하지 않습니다. 지난 날짜의 일정은 나중에 재생하지 않습니다.
도움말은 프로그램에서 열어 적용 버튼을 누르면 저장합니다. 저장 실패 시 편집 창에서 재시도할 수 있습니다.

## 검증 범위

Linux에 별도로 준비한 Mono에서 C# 5 문법으로 전체 소스를 경고 없이 컴파일했습니다.
사용자 PC에는 Mono를 설치하지 않습니다. 테스트 도구는 배포 프로그램의 의존성이 아닙니다.
핵심 데이터 시험 21개, 별도 Python CSV 파서 검증 1개, 가상 화면의 UI 시험 11개가 통과했습니다.
데이터 시험에는 줄바꿈/따옴표/한글, 저장 중 실패, 수정·재시작, 날짜 변경, 삭제 후 사진 보존,
사진 이름 충돌, CSV 출력 실패 후 미완료 목록 보존, 손상 XML 거부 등을 포함했습니다.
UI 시험에는 항목 합산, 폼을 통한 저장·수정, 저장 전 입력과 원본의 분리, 상태/날짜/검색 필터와 화면 렌더링을 포함했습니다.

Windows의 csc.exe, VBS 실행, 한셀/엑셀 연결, Windows 파일 잠금, 실제 화면 배율,
사진 선택 대화상자를 포함한 전체 사진 이동 흐름, 자정/절전/알림 팝업은 Windows에서 추가 확인해야 합니다.
가상 데이터 시험이 끝나기 전 실제 업무용 자료로 사용하지 마세요.

## Windows 확인 순서

1. VBS 빌드 성공 여부와 Build.log 확인.
2. 가상 항목 2개를 넣고 저장 후 종료·재실행.
3. 수량/비고/과거 날짜를 수정하고 해당 날짜의 CSV 확인.
4. 쉼표, 큰따옴표와 여러 줄 메모를 넣어 한셀/엑셀에서 확인.
5. 테스트용 CSV를 다른 프로그램으로 열어 잠근 상태에서 저장 결과와 재시도 확인.
6. 시험 사진 복사본 여러 개로 이동, 추가 이동, 기록 수정 후 사진명 갱신 확인.
7. 사진을 사용자가 지운 뒤 파일 없음 표시 확인.
8. 기록 영구 삭제 후 사진이 남고 날짜 CSV에서 기록이 빠졌는지 확인.
9. 같은 프로그램을 두 번 실행하여 두 번째 실행이 차단되는지 확인.
10. 시험용 일반 일정을 설정하고 실행 중/재실행 후 확인 여부 시험.
